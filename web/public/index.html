Agent teams forget. This one doesn’t.

Every agent session starts cold. Each agent keeps its own notes, and afterwards nobody can say why the team believed something.

MemoryLoom is the shared memory layer those agents are missing: one store every agent writes to through a review gate, one recall path that always shows its evidence, and a history that can answer “what did we believe on this date?”

See it working Read the numbers

The demonstration runs on a small fictional corpus — a community demo rig called Project Lantern, tended by two agents, grok and moose. Everything you see is that corpus, live from the database.

The problem

Three ways a team of agents loses its mind

Cold starts

Every session begins from nothing. Yesterday’s hard-won fact — the rig runs firmware 2.4.1 — is re-derived, re-asked, or quietly contradicted.

Private notes

Each agent remembers alone, in its own format, in its own silo. The team’s knowledge is the union of notebooks nobody else can read.

No “why”

When two agents disagree, there is no record of who claimed what, on what evidence, or who approved it. The argument restarts from zero, forever.

The live loop

Nothing enters memory unexamined

An agent proposes a memory; it never writes directly. A decision gate scores the proposal with a fixed choice — approve, reject, or escalate — and escalate always exists. Approved memories land in the truth store with their provenance attached. Recall then hands the agent not just an answer, but a receipt: the record it came from, who wrote it, and what it rests on. If a recalled item cannot produce its receipt, it is dropped before the agent sees it.

The loop is synchronous on purpose. The team watches a memory being proposed, scored and committed, and corrects it in the open. Background processes may suggest — they never silently write.

Memory

Two planes: truth below, recall above

Forgetting is a feature

Stale memories lose strength on a fixed schedule — same state, same answer, every time. Duplicates are consolidated into single entries, but only when the gate accepts the merge. Nothing quietly vanishes: a forgotten memory leaves its provenance behind.

Time travel

Every fact carries the dates it was believed between. Ask the store what the team believed on a given day and it answers from the record — not from what happens to be true now.

Learning

The team gets better at remembering, on the record

Every interaction — a proposal, a verdict, a correction, a recall that missed — is written down as a learning event. An event becomes a standing playbook lesson only by passing the same decision gate as everything else. Then the next agent recalls the lesson, receipt and all, and does the task properly the first time.

Run it

One database, one command

cp .env.example .env.local   # set DATABASE_URL (Postgres 16 + pgvector)
npm install
npm run db:init                                  # schema + migrations
DATABASE_URL=postgres://… npm run seed:web       # the Project Lantern demo corpus
DATABASE_URL=postgres://… npm run web            # this site at / · the console at /console

Agents connect over MCP (npm run mcp) and speak the same propose / recall / review surface the console renders. The console never touches a live store: it reads the demo namespace you seeded.

MemoryLoom — one shared, auditable memory brain for agent teams. The demonstration corpus (Project Lantern) is fictional, written for this demo; no real data appears anywhere on this site or in the console.
